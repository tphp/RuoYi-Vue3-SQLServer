# 开发结构目录文档生成

## 用途

扫描仓库（或指定模块）的真实目录结构，产出一份**结构说明文档**：目录树 + 各目录职责表 + 关键文件说明，用于让 AI 与团队成员快速理解工程布局。所有内容以**实际代码为准**，禁止凭记忆编造目录。

## 触发条件（满足任意一条即执行）

1. 用户要求生成/更新「项目结构文档」「模块结构说明」「开发结构目录」「目录树文档」
2. 新模块落地后需要补结构说明
3. 大规模目录调整后需要同步结构文档

## 执行步骤（严格按顺序）

### 步骤1：确定范围
- 全项目：根目录 + 后端 Maven 模块 + `ruoyi-ui` + `docs/` + `.trae/`
- 单模块：只扫该模块（如 `ruoyi-apilog`、`ruoyi-bizperm`、`docs/02-development/<module>`）
- 不确定时先问用户要「全项目」还是「指定模块」

### 步骤2：收集真实结构
- 用 Glob / `Get-ChildItem -Recurse` 收集目录与文件，**必须排除**：`target/`、`node_modules/`、`.git/`、`.idea/`、`dist/`、`.vscode/`、`*.class`、日志与临时文件
- 树深控制：默认 3~4 层；文件较多的目录只列关键文件（入口类、XML、SQL、README），其余用 `…（其余 N 个文件）` 概括
- 结构树用代码块呈现，目录后以 `#` 注释一句话职责

### 步骤3：生成文档内容
按下方模板组织，职责说明优先对照 `.trae/rules/project-rules.md` §1 模块表、§3.1 包结构、§4.1 前端目录边界。

### 步骤4：落位与命名
- 位置：全项目结构 → `docs/02-development/structure/`；模块结构 → `docs/02-development/<module>/`
- 文件名：**英文小写、短横线**，如 `project-structure.md`、`module-structure.md`
- 首行必须是中文 H1 标题，其下紧跟元信息行 `> 中文名称：xxx`（文档中心导航按此显示）
- 同步更新所属目录 `README.md` 索引表与 `docs/README.md` 索引

### 步骤5：校验（全部通过才交付）
- [ ] 目录树与真实磁盘一致（抽查 3~5 个路径，无臆造目录）
- [ ] 已排除 `target`、`node_modules` 等构建/IDE 产物
- [ ] 文件名英文短横线；首行中文 H1 + 「中文名称：」元信息
- [ ] 两级 README 索引已更新，链接可点通
- [ ] 模块职责、红绿区边界与 project-rules 一致

## 禁止事项

- ❌ 修改任何代码文件（本技能只产出文档）
- ❌ 编造不存在的目录/文件（一切以磁盘实际结构为准）
- ❌ 在 `docs/` 根目录下平铺新建文档（必须进 `02-development/<module>/`）
- ❌ 中文/全角字符作文件名；忘记「中文名称：」元信息行
