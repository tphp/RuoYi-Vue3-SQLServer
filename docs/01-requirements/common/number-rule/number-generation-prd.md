## 1. 需求背景

- 问题 / 机会描述：业务单据编号原先由各业务点自行拼装或手工填写，格式不统一、流水号易重、规则调整需发版，缺乏集中可配置的编号服务。

## 2. 需求目标

- 业务目标：编号规则可视化配置、即配即用；生成的编号全局唯一、格式可预期。
- 量化指标（如有）：并发生成不重号（数据库行级锁保证）；规则调整无需修改代码/重新发版。

## 3. 需求范围

### 包含

- [x] 编号规则的增删改查、启用/停用
- [x] 元素自由组合：常量、日期、流水号三种元素（拖拽式编排、上移/下移/删除）
- [x] 流水号策略：不循环 / 按日 / 按月 / 按年四种累计周期，支持补零与位长配置
- [x] 配置过程中实时预览最终编号格式
- [x] 按规则生成编号的统一调用接口（含日期格式支持）
- [x] 流水号使用记录（可追溯）

### 不包含（Out of Scope）

- [ ] 各业务单据接入改造（由调用方按需接入生成接口）
- [ ] 编号的作废/回收/重号修正
- [ ] 按组织或角色分级的规则权限体系

## 4. 用户与角色

| 角色 | 使用场景 | 核心诉求 |
|------|----------|----------|
| 系统管理员/配置员 | 新增或调整单据编号规则 | 可视化配置、预览即所得、启停可控 |
| 业务系统调用方 | 创建单据时获取编号 | 高并发下唯一、格式稳定、性能可接受 |
| 审计人员 | 核查编号连续性与规则变更 | 流水记录可追溯 |

## 5. 功能需求

### 功能点1：规则管理

- 描述：维护编号规则主数据（规则编码、名称、状态、备注），支持列表查询、详情、新增、修改、删除、启用/停用。
- 约束条件：停用的规则不可再生成编号；删除受关联校验保护。

### 功能点2：元素编排

- 描述：在规则下编排元素序列，元素类型为常量、日期、流水号；支持顺序上移、下移、删除。
- 交互 / 流程：选择元素类型 → 设定参数（常量文本 / 日期格式 / 流水号长度与补零）→ 组合出完整格式。

### 功能点3：流水号策略与唯一性

- 描述：流水号累计周期可选不循环、按日、按月、按年；到期自动重置；补零至配置位长。
- 约束条件：唯一性由数据库行级锁保证（见方案「唯一性保证」），同规则并发生成不重号。

### 功能点4：实时预览

- 描述：配置过程中实时展示按当前元素序列拼装出的编号示例，保存前即可确认最终格式。

### 功能点5：编号生成接口

- 描述：外部/内部调用方按规则调用统一接口获取编号；日期元素按配置格式渲染。
- 约束条件：接口幂等性要求见待确认问题；生成结果写入流水记录表。

## 6. 验收标准

- [ ] 配置一条含常量+日期+流水号的规则，预览格式与实际生成格式一致
- [ ] 并发调用同一规则生成编号，结果无重复
- [ ] 按日/按月/按年周期到期后流水号正确重置，补零位长正确
- [ ] 规则停用后调用生成接口返回明确错误
- [ ] 规则增删改查、启停在页面可正常操作且带权限控制
