# RabbitMQ 外部接口失败重试需求文档

> 中文名称：RabbitMQ 外部接口失败重试需求文档
>
> 版本：v1.2 | 日期：2026-11-18 | 状态：已确认 | 适用：本后端仓库（各分支项目通用）
>
> v1.2 修订要点（健全性分析 P0 同步）：延迟队列改固定 TTL 等级（消除队首阻塞导致的延迟失真）、
> 原始报文 AES 加密存储（解决脱敏展示与重放凭证冲突）、状态机新增「3=处理中」消费抢占
> （防外部接口被重复调用）、新增补偿巡检需求（投递丢失/消费卡死自动兜底）
>
> v1.1 修订要点：将消息管理后端能力（查询/详情/手工重推/删除终态/菜单权限）并入本期交付；本期仅不含前端页面

## 1. 需求背景

系统存在大量对外部系统（OA、ERP、CRM、MDM 等）的接口调用，当前统一通过 `ExternalApiClient` 发起。调用失败时只有两种结果：

- 业务线程直接抛出 `ServiceException`，失败即丢失，无任何补偿机会；
- 出站日志（`sys_outbound_log`）仅记录失败事实，不会自动重试。

由此带来的问题：

- 外部系统短暂抖动即可导致业务数据不一致（本系统已成功、外部系统未收到）；
- 失败调用需人工排查日志、手工补推，效率低且易漏；
- 无法回答「这条数据到底有没有同步成功」，缺少可追溯的失败记录与终态。

## 2. 需求目标

- 外部接口调用失败后**自动延迟重试**，尽量自愈。
- 每次失败都有**落库记录**（接口名、参数、失败原因、状态、重试次数），可查、可追溯。
- 重试耗尽后**自动告警**，让运维/业务方感知并介入。
- 未部署 RabbitMQ 的分支项目**不受影响**（默认关闭）。

量化指标：

- 外部系统 5 分钟内恢复的前提下，自动重试成功率 ≥ 95%（避免人工补推）；
- 失败记录可追溯率 100%（每次失败都能在库中找到对应记录）。

## 3. 需求范围

### 包含

- [ ] 外部接口调用失败后，写入本地消息表并投递 RabbitMQ
- [ ] 延迟重试（首次 30s，逐次翻倍，最多 3 次）
- [ ] 重试成功/失败的状态回写
- [ ] 重试耗尽后进入告警队列
- [ ] 告警以「操作日志 + 通知公告」形式落地
- [ ] 重试次数、延迟、开关均可配置，默认关闭
- [ ] 各分支项目可独立启用，不启用时行为与现状一致
- [ ] 提供 MQ 消息管理后端接口：分页列表、条件查询、详情、手工重推、删除终态记录
- [ ] 提供「日志管理 → MQ消息」菜单与按钮权限 SQL（`mq:message:list/query/retry/remove`）
- [ ] 补偿巡检：定时扫描投递丢失、消费卡死记录并自动重投，闭环不依赖人工
- [ ] 失败消息的原始报文加密存储，保证重试时凭证完整可用（展示字段仍脱敏）

### 不包含（Out of Scope）

- [ ] 不改造现有 `ExternalApiClient` 的日志与异常语义
- [ ] 不含 MQ 消息管理前端页面（主前端 `xxx-web`、旧前端 `ruoyi-ui` 页面另行排期；一期已具备全部后端接口，页面完成后可直接对接）
- [ ] 不引入 Kafka / RocketMQ 等其他中间件
- [ ] 不做外部接口的限流、熔断、降级策略调整
- [ ] 钉钉/企微 Webhook 告警仅预留配置，一期不启用

## 4. 用户与角色

| 角色 | 使用场景 | 核心诉求 |
|------|----------|----------|
| 业务系统（自动） | 提交外部接口调用失败后自动重试 | 失败可自愈，不丢数据 |
| 运维人员 | 查看失败记录、处理告警、手工重推 | 知道哪条失败了、失败几次、为什么失败，并能立即干预 |
| 业务人员 | 收到通知公告 | 知道哪些业务数据未同步到外部系统 |
| 开发人员 | 新接口接入重试能力 | 接入方式简单、与现有外部调用保持一致 |

## 5. 功能需求

### 功能点 1：失败落库

- 描述：外部接口调用失败时，将本次调用信息写入本地消息表（`sys_mq_message`）。
- 记录内容：接口名称、请求方式、请求地址、请求头、请求参数、失败原因、最近一次响应、状态、重试次数、下次重试时间。
- 约束：
  - 落库必须先于消息投递，保证「消息丢了数据还在」；
  - 请求头 / 请求参数两列按现有出站日志脱敏规则处理，仅用于页面展示；
  - **另存完整原始报文（含真实鉴权头）并 AES 加密**（`replay_payload` 列）：脱敏会把 `Authorization` / `token` 变成 `******`，直接用脱敏数据重放必然鉴权失败，因此重试一律解密原始报文，展示字段与重放数据彻底分离；
  - 加密密钥通过环境变量注入，开关开启且密钥缺失时启动报错（fail-fast），密钥不落库、不入 Git；
  - 单字段超长需截断，避免插入失败。

### 功能点 2：延迟重试

- 描述：失败记录投递到延迟队列，到期后由消费端重新调用外部接口。
- 流程：

  ```
  失败 → 落库（状态=待重试）→ 按下次重试档位路由到对应等级延迟队列（首次 t30）
       → 队列 TTL 到期 → 死信转投消费队列 → 消费端抢占（0→3）→ 解密重放
             ├─ 成功 → 状态=成功（DONE），记录响应
             └─ 失败 → 重试次数+1
                    ├─ < 3 次 → 重投对应等级延迟队列（t60 / t120）
                    └─ ≥ 3 次 → 转告警队列
  ```

- 约束：
  - 延迟时长按重试次数翻倍：30s → 60s → 120s，单次封顶 3600s；
  - **延迟队列按 TTL 拆固定等级队列**（如 `t30/t60/t120`，队列级 TTL + 到期死信转投消费队列），不做单队列消息级 TTL——RabbitMQ 只在队首消息过期时才检查 TTL，单队列下队头压着长延迟消息会阻塞后续短延迟消息，造成「30s 的消息等 2 分钟才被消费」的延迟失真；
  - 重试次数以数据库为准，MQ 消息只携带消息 ID，避免重复投递导致计数失真；
  - **消费前必须抢占状态（`0→3`），抢占失败的消息直接丢弃**：数据库幂等校验只能保证计数不重复累加，防不住外部接口被并发重复调用；状态抢占保证同一消息同一时刻只有一个消费者在处理；
  - 不具备重试价值的错误（如 4xx，429 除外）直接置最终失败，不做无效重试；
  - 不可解析的异常消息（毒丸）不无限重回队列，转停车场队列留档供人工排查。

### 功能点 3：状态管理

- 描述：消息状态需可查询、可区分终态。
- 状态定义：

  | 状态 | 含义 | 说明 |
  |------|------|------|
  | 0 | 待重试 | 已落库，等待到期重试 |
  | 1 | 成功 | 重调成功，终态 |
  | 2 | 最终失败 | 重试耗尽 / 不可重试，已告警，终态 |
  | 3 | 处理中 | 消费端已抢占、正在调用外部接口（`0→3` 抢占） |

- 状态流转：

  ```
  0（待重试）──消费抢占──▶ 3（处理中）──成功──▶ 1（成功，终态）
                          │
                          ├─失败且可重试──▶ 0（计数+1，重投延迟队列）
                          ├─失败且耗尽/不可重试──▶ 2（最终失败，终态，转告警）
                          └─处理超时（消费实例宕机）──▶ 由补偿巡检回收重投
  ```

- 约束：
  - **同一消息同一时刻仅允许一个消费者处理**（`0→3` 抢占，抢占失败即丢弃），从根源上防止外部接口被重复调用；
  - 终态（1/2）记录不再被消费端处理，仅作留档；
  - 「处理中」为临时态，超时未回写即视为消费卡死，由补偿巡检兜底回收（见功能点 8）。

### 功能点 4：告警

- 描述：重试次数达到上限后进入告警队列，由告警消费端统一处理。
- 告警内容：接口名称、请求地址、失败原因、重试总次数、首次失败时间。
- 落地方式：
  - 写若依操作日志（可审计）；
  - 推送到若依「通知公告」（业务方可见）；
  - 预留 Webhook 配置项（留空则跳过），一期不启用。
- 约束：告警本身失败不得影响主流程，也不得引发无限重试。

### 功能点 5：开关与配置

- 描述：所有重试参数与 MQ 连接信息均可配置。
- 可配置项：

  | 配置项 | 默认值 | 说明 |
  |--------|--------|------|
  | `ruoyi.mq.enabled` | `false` | 总开关，关闭时只直调 + 失败落库 |
  | `ruoyi.mq.retry.base-ttl-seconds` | 30 | 首次重试延迟（即最低 TTL 等级） |
  | `ruoyi.mq.retry.max-retry-times` | 3 | 最大重试次数 |
  | `ruoyi.mq.retry.max-ttl-seconds` | 3600 | 单次延迟上限 |
  | `ruoyi.mq.replay.encrypt-key` | 环境变量 | 原始报文 AES 加密密钥；开关开启时必填，缺失启动报错 |
  | `ruoyi.mq.compensation.enabled` | `true` | 补偿巡检开关（跟随总开关生效） |
  | `ruoyi.mq.compensation.pending-timeout-minutes` | 10 | 「待重试」超该时长未被消费视为投递丢失 |
  | `ruoyi.mq.compensation.processing-timeout-minutes` | 5 | 「处理中」超该时长未回写视为消费卡死 |
  | `ruoyi.mq.alert.webhook-url` | 空 | 预留，留空跳过 |
  | `spring.rabbitmq.*` | 环境变量 | 连接信息，不写死口令 |

- 约束：
  - 连接信息与加密密钥一律通过环境变量注入，禁止提交到 Git；
  - 延迟等级参数（`base-ttl-seconds` / `max-ttl-seconds` / `max-retry-times`）调整后，旧等级队列参数不会自动变更，需删除旧队列后重启重建，文档与运维手册需注明。

### 功能点 6：接入方式

- 描述：业务方通过统一门面发起外部调用，失败自动进入重试链路。
- 交互：业务代码调用重试门面 → 门面内部先直调 → 成功直接返回；失败则落库投递并返回失败结果，不阻塞业务流程。
- 约束：一期只接入 1~2 个关键接口试点，验证闭环后再铺开。

### 功能点 7：消息管理（后端接口）

- 描述：为运维人员提供失败消息的可视化运维入口的后端能力，前端页面后续排期对接。
- 能力：

  | 能力 | 说明 |
  |------|------|
  | 分页列表 | 按接口名（模糊）、状态、重试次数、创建时间范围筛选；大字段不进列表 |
  | 详情 | 返回请求头、请求参数、失败原因、最近响应等全字段 |
  | 手工重推 | 对「待重试 / 最终失败」消息触发一次立即重试，重置计数后重新进入重试闭环 |
  | 删除 | 仅允许删除终态（成功 / 最终失败）记录 |

- 约束：
  - 手工重推必须先更新库再投递，保持「先落库后发 MQ」原则；
  - 重推与消费端并发时用「状态 + 重试次数」乐观校验，避免重复累加；
  - **「处理中（`status=3`）」消息禁止手工重推**：消费端正持有该消息调用外部接口，此时重推会与正在执行的外部调用并发，必须拒绝并提示稍后重试；
  - 详情接口**不返回加密原始报文字段**（`replay_payload`），列表/详情展示的请求头、请求参数均为脱敏数据；
  - 所有写操作走 `@PreAuthorize` 权限校验并写操作日志；
  - 删除为物理删除，删除后不可追溯，仅终态可删且留操作日志审计；
  - MQ 总开关关闭时，重推接口明确返回「MQ 未启用」，不静默成功。

### 功能点 8：补偿巡检（兜底自愈）

- 描述：MQ 链路存在两类「无消息可消费」的卡死场景，需定时任务扫描数据库兜底重投，闭环不依赖人工：
  - **投递丢失**：落库成功但 MQ 投递失败/丢消息，记录停在「待重试（0）」却永远无人消费；
  - **消费卡死**：消费者抢占成功（0→3）后实例宕机，状态永远停在「处理中（3）」。
- 处理规则：

  | 场景 | 判定 | 处理 |
  |------|------|------|
  | 投递丢失 | `status=0` 且超过 `pending-timeout-minutes` 未被消费 | CAS 抢占后按当前重试档位重新投递 |
  | 消费卡死 | `status=3` 且超过 `processing-timeout-minutes` 未回写 | CAS 抢占后重新投递（计数沿用，不额外+1） |
  | 不可重放 | 加密报文解密失败 | 直接置最终失败并告警，避免无效循环 |

- 约束：
  - 巡检经若依定时任务（`sys_job`）注册调度，执行频率 cron 可调、任务可暂停，不额外引入定时组件；
  - 多实例部署下分批扫描、逐条 CAS 抢占，保证多节点安全；
  - 巡检自身异常仅记日志，不影响主流程。

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 可用性 | RabbitMQ 不可用时业务不受阻断；开关关闭时行为与现状完全一致 |
| 可靠性 | 先落库后投递；开启发布确认；消费端手动 ack；投递丢失 / 消费卡死由补偿巡检兜底重投，全链路不依赖人工 |
| 幂等性 | 同一消息重复投递不重复处理，计数不重复累加；消费前状态抢占，外部接口不被重复调用 |
| 延迟准确性 | 固定 TTL 等级队列消除队首阻塞，短延迟消息不被长延迟消息拖住，延迟不失真 |
| 可观测 | 失败记录含接口名/参数/失败原因/次数；重试过程可在日志中追踪；毒丸消息留档停车场队列可排查 |
| 安全 | 连接口令与加密密钥走环境变量；展示字段按脱敏规则存储；重放原始报文 AES 加密；密钥缺失时启动报错 |
| 兼容性 | 数据库为 SQL Server，SQL 需符合项目方言规范 |

## 7. 验收标准

- [ ] 编译通过：`mvn -pl ruoyi-admin -am compile -DskipTests`
- [ ] 总开关关闭时：无 RabbitMQ 也能正常启动，无报错；调用失败仅落库不重试
- [ ] 开启后启动自动创建交换机、TTL 等级队列（`t30/t60/t120`）、消费 / 停车场 / 告警队列，绑定关系正确（管理台可查）
- [ ] **延迟不失真**：先向 `t120` 压入一条 120s 消息，再向 `t30` 投一条 30s 消息，30s 级消息按期到达消费队列，不被长延迟消息阻塞
- [ ] 外部接口首次调用失败：本地消息表新增记录，状态为「待重试」，重试次数 0，30s 后消费端触发
- [ ] **消费抢占生效**：同一消息并发 / 重复投递时，外部接口仅被调用一次，后到的消息直接丢弃
- [ ] 重试成功：状态变为「成功」，记录响应内容
- [ ] 连续失败：延迟依次为 30s、60s、120s，重试次数逐次 +1
- [ ] 第 3 次仍失败：状态变为「最终失败」，告警队列收到消息，操作日志与通知公告各新增一条
- [ ] **重放凭证完整**：带 `Authorization` 头的失败调用重放成功（外部系统收到真实 token 而非脱敏值 `******`）；列表 / 详情接口不返回加密原始报文字段
- [ ] **补偿自愈——投递丢失**：模拟只落库不发 MQ，超时后「待重试」记录被巡检自动重投消费
- [ ] **补偿自愈——消费卡死**：模拟抢占后不回写，超时后「处理中」记录被巡检自动回收重投
- [ ] 外部接口返回 4xx（非 429）：不重试，直接置「最终失败」并告警
- [ ] 业务事务回滚时，失败记录仍保留在消息表
- [ ] 出站日志可通过 `message_id` 串起首次失败与各次重试
- [ ] 消息列表支持接口名模糊、状态、次数与时间范围筛选，分页总数与列表一致，大字段不返回
- [ ] 消息详情可查看请求头（脱敏）、请求参数（脱敏）、失败原因、最近响应
- [ ] 手工重推后状态回到「待重试」、重试次数归零，30s 后被消费；并发冲突返回「状态已变更，请刷新」
- [ ] 对「成功」状态重推返回「已成功的消息无需重推」；对「处理中（status=3）」重推返回「消息处理中，请稍后重试」；删除待重试记录被拒绝
- [ ] 重推、删除操作在操作日志中可查，权限不足返回 403
- [ ] 菜单 SQL 执行后「日志管理 → MQ消息」可见，三个按钮权限可分别授权
- [ ] **密钥校验**：开关开启且加密密钥未配置时启动失败并给出明确提示
- [ ] 毒丸消息（构造不可解析消息体）进入停车场队列留档，不无限重回消费队列

## 8. 已确认决策

| 项 | 决策 |
|----|------|
| 模块落点 | 新建 🟢 `ruoyi-mq` 模块，不修改 🔴 框架模块 |
| 一期告警渠道 | 操作日志 + 通知公告；Webhook 预留不启用 |
| 接入范围 | 先试点 1~2 个关键外部接口 |
| 重试参数 | 30s 起、最多 3 次、封顶 3600s，全部可配置 |
| 管理能力合并 | 消息管理后端接口与菜单权限 SQL 纳入本期；前端页面另行排期 |
| 重推并发控制 | 以「状态 + 重试次数」乐观校验，冲突时提示刷新重试 |
| 删除策略 | 物理删除，仅终态可删，删除操作写操作日志留审计 |
| 延迟拓扑（P0-1） | 固定 TTL 等级队列（`t30/t60/t120`，队列级 TTL + 到期死信转投），不做单队列消息级 TTL，消除队首阻塞；调整 TTL 配置需删除旧等级队列重建 |
| 重放凭证（P0-2） | 展示字段脱敏 + 完整原始报文 AES 加密分开存储；密钥环境变量注入，开关开启时必填，解密失败按不可重试终态处理 |
| 并发防重（P0-3） | 状态机新增「3=处理中」，消费前 CAS 抢占 `0→3`，抢占失败消息直接丢弃；处理中消息禁止手工重推 |
| 卡死兜底（P0-4） | 新增补偿巡检定时任务（经 `sys_job` 注册、cron 可调、可暂停），扫描「待重试 / 处理中」超时记录 CAS 抢占重投，多实例安全 |
| 重投入口（P0-5） | `ExternalApiClient` 内部抽取统一执行方法并新增重投入口，返回含 HTTP 状态码的结果对象供按状态码决策；现有三个方法语义不变 |
