# 需求文档（PRD） - 外部系统接口对接（API Key 认证）

>

## 1. 需求背景

- 问题 / 机会描述：OA、ERP、CRM、MDM 等外部系统需要程序化调用本系统接口，不能依赖个人账号口令，需要一套可发放、可停用、可过期的应用级认证机制。

## 2. 需求目标

- 业务目标：以 API Key + Secret 换取短时效 JWT Token 的方式，复用若依现有认证体系对外开放接口。
- 量化指标（如有）：令牌有效期 30 分钟（1800 秒）；密钥停用/过期后立即失效。

## 3. 需求范围

### 包含

- [x] API 密钥管理：新增、修改、停用/启用、过期时间设置（前端 `system/apiKey` 页面）
- [x] 对外认证接口 `POST /api/auth/token`（apiKey + apiSecret 换取 OAuth2.0 格式 JWT）
- [x] 对外业务接口统一路径前缀 `/api/**`，携带 `Authorization: Bearer {token}`
- [x] 独立认证过滤器 `ApiKeyAuthenticationFilter`，对缺令牌/无效/停用/过期等 7 类错误返回明确信息
- [x] 密钥唯一性约束（`uk_api_key` 唯一索引）

### 不包含（Out of Scope）

- [ ] 外部系统侧的接入实现与联调
- [ ] 按密钥/按接口的细粒度授权（当前密钥认证身份为 admin）
- [ ] 调用配额、限流、用量计费
- [ ] Secret 的轮换与双密钥并存机制

## 4. 用户与角色

| 角色 | 使用场景 | 核心诉求 |
|------|----------|----------|
| 平台管理员 | 为外部系统发放/停用密钥、设置有效期 | 发放简单、可随时吊销 |
| 外部系统（程序） | 换取 Token 后调用 `/api/**` 接口 | 流程标准、错误信息明确可自处理 |
| 审计人员 | 核查密钥使用与调用行为 | 密钥状态与操作留痕 |

## 5. 功能需求

### 功能点1：API 密钥管理

- 描述：维护 `sys_api_key`（应用名如 `smc_crm`/`smc_mdm`、apiKey、apiSecret、状态、过期时间、备注），支持 CRUD 与启停。
- 约束条件：apiKey 全局唯一；Secret 仅用于换取 Token。

### 功能点2：令牌换取

- 描述：`POST /api/auth/token` 提交 apiKey+apiSecret，成功返回 `access_token`/`token_type=bearer`/`expires_in=1800`，失败返回 `code=401` 与原因。
- 约束条件：复用现有 JWT 签发与校验机制。

### 功能点3：对外业务接口认证

- 描述：`/api/**` 前缀接口经 `ApiKeyAuthenticationFilter` 校验 Bearer Token；认证通过的身份为 admin（userId=1），不受数据权限限制、可查询全部数据。
- 约束条件：错误响应覆盖 7 类场景（缺令牌、令牌无效、缺 API Key 信息、密钥不存在、已停用、已过期、解析失败）。

### 功能点4：密钥状态控制

- 描述：停用/启用、过期时间到期后立即拒绝换取与访问。

## 6. 验收标准

- [ ] 有效密钥可成功换取 Token，并携带 Token 访问 `/api/**` 接口
- [ ] 停用或过期的密钥换取 Token 返回 401，且已签发的 Token 后续请求被拒绝
- [ ] 各类错误返回信息与方案中的错误对照表一致
- [ ] 页面可完成密钥的新增、修改、启停操作并带权限控制

## 7. 疑问与待确认

- [ ] **权限范围**：密钥认证身份为 admin、可查全部数据，是否存在越权面？是否需要按密钥限定可访问的接口清单？
- [ ] **Secret 存储安全**：`api_secret` 直接存库（方案未见加密说明），是否需要哈希/加密存储与脱敏展示？
- [ ] 是否需要调用日志与限流（可与 `ruoyi-apilog` 出站/入站日志联动）？
- [ ] Token 30 分钟有效期对批量长任务场景是否足够，是否需要刷新令牌机制？
