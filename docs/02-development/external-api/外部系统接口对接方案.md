# 外部系统接口对接方案

## 方案概述

为 OA、ERP、CRM、MDM 等外部系统提供基于 **API Key + JWT Token** 的认证机制，复用若依框架现有的 JWT 认证体系。

## 认证流程

```
外部系统 → 使用 API Key + Secret 调用 /api/auth/token → 获取 JWT Token → 后续请求携带 Token 调用 /api/** 接口
```

## 安全机制

- ✅ **API Key**：应用标识（如 `smc_crm`、`smc_mdm`）
- ✅ **API Secret**：密钥（仅用于换取 Token，不传输）
- ✅ **JWT Token**：复用现有认证机制
- ✅ **Token 有效期**：30 分钟（1800 秒）
- ✅ **API Key 状态控制**：可停用/启用
- ✅ **API Key 过期时间**：可设置过期时间

## 实现要点

### 1. 对外认证接口

- **路径**：`POST /api/auth/token`
- **请求参数**：
  ```json
  {
    "apiKey": "smc_crm",
    "apiSecret": "sk_2dce57877344470ebdf1aa8d5000a0c6"
  }
  ```
- **成功响应**（OAuth2.0 标准格式）：
  ```json
  {
    "access_token": "eyJhbGciOiJIUzUxMiJ9.xxxx",
    "token_type": "bearer",
    "expires_in": 1800
  }
  ```
- **错误响应**：
  ```json
  {
    "msg": "API Key不存在",
    "code": 401
  }
  ```

### 2. 业务接口调用

- **路径前缀**：`/api/**`
- **认证方式**：`Authorization: Bearer {access_token}`
- **权限控制**：API Key 认证的用户拥有 admin 权限（userId=1），不受数据权限限制，可查询全部数据

### 3. 认证过滤器

对外接口使用独立的 `ApiKeyAuthenticationFilter`，提供详细的错误信息：

| 错误情况 | 返回信息 |
|----------|----------|
| 缺少 Token | "缺少有效的认证令牌" |
| Token 无效 | "令牌无效" |
| Token 中缺少 API Key | "令牌中缺少API Key信息" |
| API Key 不存在 | "API Key不存在" |
| API Key 已停用 | "API Key已被停用" |
| API Key 已过期 | "API Key已过期" |
| Token 解析失败 | "令牌解析失败" |

### 4. 外部系统调用示例

```java
// 第一步：获取 Token
Map<String, String> authParams = new HashMap<>();
authParams.put("apiKey", "smc_crm");
authParams.put("apiSecret", "sk_2dce57877344470ebdf1aa8d5000a0c6");

HttpResponse<String> authResponse = client.send(
    HttpRequest.newBuilder()
        .uri(URI.create("http://localhost:8080/api/auth/token"))
        .header("Content-Type", "application/json")
        .POST(BodyPublishers.ofString(JSON.toJSONString(authParams)))
        .build(),
    BodyHandlers.ofString()
);

JSONObject authResult = JSON.parseObject(authResponse.body());
String accessToken = authResult.getString("access_token");

// 第二步：使用 Token 调用业务接口
HttpResponse<String> businessResponse = client.send(
    HttpRequest.newBuilder()
        .uri(URI.create("http://localhost:8080/api/system/user/list"))
        .header("Authorization", "Bearer " + accessToken)
        .GET()
        .build(),
    BodyHandlers.ofString()
);
```

### 5. 接口路径规范

| 路径 | 说明 | 认证方式 |
|------|------|----------|
| `/api/auth/token` | 获取 Token | API Key + Secret |
| `/api/**` | 对外业务接口 | JWT Token |
| 其他路径 | 内部接口 | 原有认证方式 |

### 6. 如何开发对外接口

#### 6.1 创建 Controller

在 `ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/api/` 目录下创建新的 Controller：

```java
package com.ruoyi.web.controller.system.api;

import java.util.List;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import com.ruoyi.common.core.controller.BaseController;
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.xxx.domain.XxxEntity;
import com.ruoyi.xxx.service.IXxxService;

/**
 * @author Zhang zhan
 * @date 2026-06-24
 */
@RestController
@RequestMapping("/api/xxx")
public class ApiXxxController extends BaseController
{
    @Autowired
    private IXxxService xxxService;

    /**
     * 查询列表
     */
    @GetMapping("/list")
    public AjaxResult list(XxxEntity entity)
    {
        List<XxxEntity> list = xxxService.selectXxxList(entity);
        return success(list);
    }

    /**
     * 获取详情
     */
    @GetMapping("/{id}")
    public AjaxResult getInfo(@PathVariable Long id)
    {
        XxxEntity entity = xxxService.selectXxxById(id);
        return success(entity);
    }
}
```

#### 6.2 路径规范

- **路径前缀**：必须以 `/api/` 开头
- **模块路径**：`/api/{模块名}/` 如 `/api/customer/`、`/api/order/`
- **自动认证**：所有 `/api/**` 路径会自动经过 `ApiKeyAuthenticationFilter` 认证

#### 6.3 注意事项

1. **数据权限**：API Key 认证的用户拥有 admin 权限，不受 `@DataScope` 数据权限限制
2. **Service 层**：可以直接调用 Service 层方法，无需特殊处理
3. **返回格式**：使用 `AjaxResult.success()` 返回标准格式
4. **异常处理**：框架会自动处理异常，返回统一错误格式

## 优势

- ✅ 复用现有 JWT 认证机制，无需额外开发
- ✅ 外部系统拿到 Token 后，调用方式与内部系统一致
- ✅ 实现简单，维护成本低
- ✅ API Key 拥有 admin 权限，不受数据权限限制
- ✅ 详细的错误信息，便于排查问题
- ✅ 支持 API Key 停用和过期控制
